通讯接线与摄像头参数由客户工程提供。无线芯片选择对应适配库，摄像头驱动按配置编译；通用业务和摄像头服务以静态库交付。

01 / 从 board.json 开始

选择硬件修改 p4_hosted 与 camera。以 PCB 接线为准，示例 GPIO 不能直接套到其他模组。
编译客户工程SDK 的 CMake 自动生成驱动配置和板级绑定源文件，不需要客户重新编译 GAgent .a。
检查生效结果构建期校验冲突；启动前可 probe；推流日志验证原生模式和输出配置。
替换摄像头或原生模式、切换无线芯片时，使用新的 build 目录和 sdkconfig 路径。sdkconfig.defaults 不会自动覆盖已存在的配置；SDK 会拒绝不匹配的旧配置。
idf.py -B build-camera -D SDKCONFIG="$PWD/build-camera/sdkconfig" build

在 project.cmake 前包含 gagent-sdk/gagent-sdk.cmake，在 project() 后调用 gagent_sdk_check()。SDK 会生成 build/gagent-sdk/gagent_board_binding；这些文件只有配置值，不包含 GAgent 实现源码。勿修改 SDK 包内部文件，否则哈希校验会失败。

02 / 通讯芯片与引脚

通讯配置统一写在客户工程 board.json 的 p4_hosted 对象中。SDK 根据 chip 链接对应适配库，再将总线引脚交给客户侧 ESP-Hosted 配置；POWER 的引脚、极性和延时由自动生成的板级绑定传入。无需再修改 SDK 源码或在 C++ 中重复设置电源。

参数范围 / 默认说明
p4_hosted.chipesp32c5 / esp32c6 / esp32c61选择已发布的无线 .a；必须与实际协处理器一致。
transportsdio / spi必须与所选适配库的构建接口一致；当前三芯片包为 SDIO。
reset_pin / reset_active_highGPIO 0–54 / true协处理器 RESET 引脚和有效电平，不是摄像头 RESET。
power_pin / power_active_high-1 / true-1 表示无软件控制电源。由生成代码自动传给 SDK。
power_delay_ms0–10000 / 20 ms供电后等待时间。
reserved_pinsGPIO 数组板上已占用引脚；不得与通讯、摄像头重复。
sdio.clk_pin / cmd_pinGPIO 0–54SDIO CLK、CMD；按实际 PCB 原理图配置。
sdio.data_pins四个 GPIO，顺序 D0、D1、D2、D3本版固定 4-bit、slot 1，不提供任意总线宽度切换。
sdio.clock_khz400–50000 kHz当前示例 40000；改频率仍需满足线路和从机能力。
sdio.reset_delay_ms100–10000 ms协处理器复位等待；示例 1500。
spi.clk_pin / mosi_pin / miso_pin / cs_pinGPIO 0–54仅适用于另行构建的 SPI 适配包。
spi.handshake_pin / data_ready_pinGPIO 0–54SPI 握手与数据就绪。
spi.clock_mhz / mode1–40 MHz / 0–3SPI 总线频率和模式。

芯片与静态库的对应关系

radio/esp32c5/libgagent_wireless.a   + libgagent_p4.a
radio/esp32c6/libgagent_wireless.a   + libgagent_p4.a
radio/esp32c61/libgagent_wireless.a  + libgagent_p4.a

这些 .a 均运行在 P4 主芯片上，是针对不同通讯芯片配置构建的主机适配库，并不是烧入 C5/C6/C61 的从机固件。实际无线芯片仍需运行与当前 ESP-Hosted 主机版本、传输方式匹配的从机固件。本例完整包提供三个芯片的 SDIO 变体。

P4 + C61 的完整接线示例

{
  "p4_hosted": {
    "chip": "esp32c61",
    "transport": "sdio",
    "reset_pin": 13,
    "reset_active_high": true,
    "power_pin": -1,
    "power_active_high": true,
    "power_delay_ms": 20,
    "reserved_pins": [
      2,
      12,
      52,
      53,
      54
    ],
    "sdio": {
      "cmd_pin": 19,
      "clk_pin": 18,
      "data_pins": [
        14,
        15,
        16,
        17
      ],
      "clock_khz": 40000,
      "reset_delay_ms": 1500
    }
  }
}

此处数值对应现有测试板，不能作为其他 PCB 的通用引脚定义。选 C5 或 C6 时，除了改 chip，还要按客户实际原理图修改所有相关 GPIO、复位极性和时序。

选择与生效规则

  1. 优先修改 board.json 的 p4_hosted.chip。SDK 自动链接同名目录中的无线库；缺失变体立即报错。
  2. 也可传入 CMake 变量 GAGENT_SDK_RADIO。若工程同时存在 board.json，两者必须一致，不能用变量悄悄覆盖板级声明。
  3. 更改芯片或接线后，用新 build 和新 SDKCONFIG 编译客户工程。SDK 检查实际 sdkconfig，防止旧引脚或旧芯片配置继续生效。
  4. 同一芯片、同一 transport 的引脚改动不需要重新编译 GAgent .a。SDIO 与 SPI 之间切换，则需要另行交付对应 transport 的适配库；仅改 JSON 无法改变已发布变体的接口能力。
  5. 运行中不能更换引脚或芯片。SDK 在初始化 Hosted 之前处理电源，Wi-Fi 与 BLE 共用同一条通讯链路。
idf.py -B build-c61 -D SDKCONFIG="$PWD/build-c61/sdkconfig" -D GAGENT_SDK_RADIO=esp32c61 build

C++ 的 ApplicationConfig::hosted_power.pin 默认值为 -2，表示使用 board.json。只有确需手工覆盖电源时才填写该字段；-1 表示 SDK 不控制电源。板级 JSON 中 power_pin 只能是 -1 或实际 GPIO，不能写 -2。

GPIO 24、25 保留给 USB Serial/JTAG。无线、摄像头和其他已声明设备不能重复占用引脚。仅更改引脚不需要更换 .a；更改 transport 需要对应接口的适配包。配置在启动前确定，运行中不允许重接总线。

03 / 首批摄像头与原生模式

依据工程锁定的 Espressif esp_cam_sensor 驱动选取。以下是 SDK 提供的模式目录，不表示已插入设备或所有模组均完成实测。SC202CS 在官方列表中也称 SC2356。

参数范围 / 默认说明
SC2336 · 默认RAW8_1024X600_30FPS1024 × 600 · 30 fps · RAW8 · 2 lane
SC2336RAW8_1280X720_30FPS1280 × 720 · 30 fps · RAW8 · 2 lane
SC2336RAW8_1920X1080_30FPS1920 × 1080 · 30 fps · RAW8 · 2 lane
OV2710 · 默认RAW10_1280X720_25FPS1280 × 720 · 25 fps · RAW10 · 1 lane
OV5647 · 默认RAW10_1920X1080_30FPS1920 × 1080 · 30 fps · RAW10 · 2 lane
OV5647RAW10_1280X960_BINNING_45FPS1280 × 960 · 45 fps · RAW10 · 2 lane
SC202CS · 默认RAW8_1280X720_30FPS1280 × 720 · 30 fps · RAW8 · 1 lane
SC202CSRAW10_1600X900_30FPS1600 × 900 · 30 fps · RAW10 · 1 lane

模式名是 capture_mode 的精确取值。所有模式使用 24 MHz XCLK；原生 45 fps 模式的 SDK 编码输出仍限制到 30 fps。模式的 lane 数由驱动配置决定，CSI 差分信号必须按硬件引脚连接，不能像普通 GPIO 任意重映射。

OV2640、OV3660 等 DVP 摄像头、USB UVC、任意新传感器并未因此获得支持。本版只接通上述 MIPI-CSI 模式。新增型号必须同时提供驱动、合法模式和必要的 ISP 调校。

参考：Espressif 传感器驱动说明 · 驱动接口说明。实际依赖版本以交付包 sdk-manifest.json 为准。

04 / 摄像头接线与上电

参数范围 / 默认说明
enabledtrue / false必须匹配 SDK 是否包含摄像头能力。
sensorsc2336 / ov2710 / ov5647 / sc202cs选择客户工程编译的 ESP 传感器驱动；同一 SDK 摄像头 .a 可复用。
capture_mode见型号表原生采集模式。省略使用该型号默认模式；不是编码输出尺寸。
i2c_port0–1 / 0SDK 创建并持有 I²C 总线；本版尚无复用外部总线的接口。
sda_pin / scl_pinGPIO 0–54SCCB/I²C 管脚；不得与其他已占用 GPIO 冲突。
i2c_hz100000–400000 Hz / 100000SCCB 通讯频率。
xclk_pin-1 或 GPIO 0–54-1：模组提供外部时钟，SDK 不生成 XCLK。
xclk_hz24000000 Hz首批模式均要求 24 MHz；外部时钟也须匹配。
reset_pin / pwdn_pin / power_pin-1 或 GPIO 0–54-1 表示未连接；三者是不同控制信号。
reset_active_highfalse默认低电平复位；SDK 统一执行复位时序。
pwdn_active_hightrue默认高电平掉电；初始化时拉到非有效电平。
power_active_hightrue电源使能的有效电平。
power_delay_ms0–10000 ms / 20供电后等待；当前 SC2336 板使用 100。
reset_hold_ms / reset_release_ms0–10000 ms / 各 10复位有效脉冲长度、释放后等待时间。
buffer_count2–4 / 2V4L2 采集缓冲个数；增加会占用更多内存。

顺序：建立 SCCB 总线 → 打开电源 → 等待 power_delay_ms → 拉住 RESET、释放 PWDN → 启动 XCLK（如有）→ 等待 reset_hold_ms → 释放 RESET → 等待 reset_release_ms → 探测传感器。模组可能自带时钟或电源管理，必须按模组要求填写。

05 / 采集模式、输出与码率

采集尺寸 ≠ 编码输出尺寸。capture_mode 决定传感器原始画面；width、height、fps 决定后续转换与 H.264 输出。当前只支持受校验的缩小和降帧，不会自动替客户选择其他模式。

参数范围 / 默认说明
width / height≥160×120；不超过原生模式H.264 输出尺寸；宽须为 16 的倍数，高须为偶数。默认 640×360。
宽高比默认保持原生比例保留历史 SC2336 1024×600 → 640×360 拉伸；其他不同比例组合拒绝。未实现任意裁剪/旋转。
fps / fps_den1–min(原生 fps,30) / 1输出帧率；当前仅支持整数。分母为未来扩展预留，其他值明确报错。
bitrate100000–10000000 bps / 600000初始编码目标码率；10 Mbps 是配置上限，不是网络吞吐保证。
adaptive_bitratetrue是否根据认证的 RTCP 丢包反馈调整目标码率。
bitrate_min0 或 100000–10000000 bps0 自动取 min(250000, bitrate)。
bitrate_max0 或 100000–10000000 bps0 自动取 bitrate。必须 min ≤ target ≤ max。
gop_frames0–300 / 00 自动取输出 fps，即约每秒一个关键帧；C API 中使用归一化后的非零值。
qp_min / qp_max0–51 / 25、45H.264 量化范围，min ≤ max；较低 QP 通常需要更多码量。
编码格式 / 码控模式H.264 / ESP 编码器默认码控未公开 CBR/VBR、profile、JPEG 等无后端实现的选择项。ABR 与编码器码控是不同概念。
adaptive_bitrate=false 表示保持编码目标码率，不保证每秒输出字节完全相同。打开自适应后，SDK 根据 RTCP 丢包反馈降码率，持续健康反馈后逐步恢复；没有新反馈时保持当前值。

06 / 修改后何时生效

参数范围 / 默认说明
无线芯片 / transport重新选择适配包并编译客户工程不需要重编译已包含变体的 SDK。
摄像头型号 / capture_mode编译客户工程并重启客户的 ESP 驱动与原生模式随配置选择；通用摄像头 .a 不变。
接线、时序、输出分辨率 / fps / GOP / QP应用启动前配置；修改后重启board.json 提供默认值，也可通过 configure 覆盖运行参数。
目标码率 / 自适应开关 / 上下限运行中可提交媒体线程应用；需检查 completed_id 和 error。

当前完整配置在第一次 service.sync() 或 probe 时锁定。停止推流不会解锁硬件配置；要改变接线、分辨率、帧率、QP 或 GOP，需要重新启动应用。运行中仅支持独立的码率策略接口。不得在不同任务中并发初始化或配置。

08 / 生成一份可用的配置

以下以现有 P4 + C61 板的接线生成完整 board.json 示例。更换摄像头模组时，务必重新核对引脚、电源极性、CSI lane 和外部时钟。生成器只展示已实现参数。



09 / C 与 C++ 接口
头文件：gagent/camera/config.h。结构体使用固定宽度字段与内嵌字符串；配置会复制，不保留调用者临时字符串。以 get_defaults 初始化 struct_size 和 abi_version，不要手工省略它们。
#include "gagent/camera/config.h"

gagent_camera_config_t cfg;
gagent_camera_get_defaults(&cfg); // 客户 board.json 生成的默认值
cfg.video.fps_num = 15;
cfg.video.gop_frames = 30;
cfg.video.bitrate = {800000, 250000, 1200000, 1};
int error = gagent_camera_configure(&cfg);
if (error != 0) { /* 处理错误，不能继续假定参数成功 */ }

// 可选：应用启动前验证接线、传感器检测和原生模式。
// probe 不启动网络推流；会锁定初始化配置。
gagent_camera_probe_result_t detected{};
error = gagent_camera_probe(&detected);
// detected.capture 是验证过的原生模式；output 是计划输出，非实测帧率。

// 启动应用、由业务开始推流后，可提交码率策略。
gagent_camera_bitrate_t policy{600000, 200000, 1000000, 1};
uint32_t id = 0;
error = gagent_camera_set_bitrate(&policy, &id);
// 返回 0 仅表示已排队。在正常业务 tick 中查询，不要忙等待。
gagent_camera_bitrate_status_t status{};
gagent_camera_get_bitrate_status(&status);
if (error == 0 && status.completed_id == id) {
    // status.error == 0 表示策略已应用或保存待下一次会话使用。
    // active 表示有会话，current_bps 是编码目标值，不是网络实测吞吐。
}
gagent_camera_mode_count / mode_at 枚举 SDK 模式目录；gagent_camera_validate 检查参数合法性；configure 还会拒绝与客户编译的 sensor / capture_mode 不同的模式。get_config 返回启动配置，不代表实测帧率。码率策略在重连后继续有效，重启设备后回到板级默认值。
公共校验返回值：0 成功；1 参数非法；2 不支持；3 状态不允许；4 已有未完成请求。硬件 probe 和异步执行错误可能保留 ESP 后端错误码，必须按非零失败处理。


10 / 验证范围与排错
构建通过不等于模组硬件验证通过。新增型号需在对应实物上验证供电、时钟、检测、稳定采集与推流。实测记录单独保存，本文不把模式目录当作全型号实测报告。
参数范围 / 默认说明
SDK config mismatch旧 sdkconfig 未更新使用新的构建目录和 SDKCONFIG 路径；不要绕过校验。
Hosted GPIO conflicts / Camera GPIO conflicts重复占用或保留 GPIO对照 PCB，检查 p4_hosted.reserved_pins 和其他设备。
camera sensor unavailable未探测到配置型号检查实际型号、SCCB、供电、PWDN、RESET、XCLK。
Detected sensor mode differs原生模式与请求不一致重新生成客户 sdkconfig；确认 capture_mode 为已支持精确值。
GAGENT_CAMERA_STATE配置已锁定或服务尚未启用初始化配置必须在 probe / application start 前；码率请求要在服务启动后。
GAGENT_CAMERA_BUSY前一个码率请求尚未完成查询执行状态后再提交；不要反复覆盖待执行请求。
码率不恢复 / no recent RTCP feedback反馈缺失或不满足恢复条件无反馈时保持码率；检查接收端 RTCP 和网络。
镜像容量、内存、实际帧率和无线链路仍限制最终输出。驱动没有实现的曝光、白平衡、镜像、旋转、CBR/VBR 选择等，本版不提供会被静默忽略的配置字段。
