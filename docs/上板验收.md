# P4 上板验收

构建和主机测试不能代替实机验收。以下项目需要连接测试板和 App 后逐项记录结果。

## 准备

使用 WT9932P4C61-TINY（P4＋C61 SDIO、16MB Flash、32MB PSRAM）及 SC2336 摄像头，C61 已有匹配无线从机固件。确认测试后端可用，并准备支持测试产品的机智云 App 和观看端。

首次覆盖其他固件前备份 Flash。如果 GData 中已保存不同 PK 或 PS，应用会拒绝启动；明确清理测试设备的 GData 双副本后再试。正常重新配网不要擦除设备身份。

## 配网和 IoT

1. 无 Wi-Fi 配置启动：红灯闪烁，出现 BLE 广播，用支持 BLE V2 的 App 完成配网。
2. 联网过程保持红闪；出现 `IoT MQTT ready` 后应亮绿灯。
3. 修改 `feed_portion`，核对日志字段名、App 查询与上报值。状态变化最多每秒上报一次，空闲每 10 秒完整上报。
4. 调用 `product::request_pairing()`，即使此前在线也应红闪；完成重新配网后恢复绿灯。
5. BOOT 按住满 5 秒：日志出现 `Wi-Fi configuration cleared; restarting for BLE pairing`，设备重启后进入 BLE 配网，且身份和绑定信息保留。一直按住跨越重启不得连续重置，松手也不得产生推流请求；重新配网后检查设备仍为同一身份。

## 按键和视频

1. 在线绿灯时短按 BOOT，日志显示开始请求接受，同时蓝灯闪烁。建立 WebRTC 连接后蓝灯常亮，并在观看端确认持续有视频。
2. 再按一次，推流停止，实际会话关闭后恢复绿灯。
3. 分别用 App 下发 `start_stream=true/false`，验证与按键一致；交替操作两种入口，确认状态上报一致。
4. 短按在松手后触发；快速抖动不应重复启停，按住不足 5 秒不应重置。长按满 5 秒只重置 Wi-Fi，不应先开/关推流。上电按住 BOOT 不应自动推流或重置，松开再按才触发。
5. 后端不可用、仍在重试时应蓝闪，不应常亮；建立连接期间再次按键，应能取消启动及后续重试。
6. 推流时断开路由器，应立即转为红闪；恢复后 SDK 自动重连，连接中应蓝闪，实际恢复推流才蓝灯常亮。掉线期间按键停止，网络恢复后不应自行继续推流。
7. 离线开始请求应被拒绝且 `start_stream` 不变；检查日志返回码，恢复联网后可重新开始。
8. 重启 P4，确认 Wi-Fi 保留，推流默认关闭并恢复绿灯；不持久化上一次按键推流意图。

`start_stream` 是已接受的控制意图，蓝闪表示等待连接，蓝灯常亮表示摄像头服务报告已连接；最终视频质量、端到端延迟以观看端为准。其余喂食、定时和传感器字段仍是内存示例。

记录测试日期、SDK 清单哈希、硬件/App 版本、每项结果和相关日志。基础联网已烧录验证；用户已反馈按键可用，完整视频及异常场景仍需逐项验收。
